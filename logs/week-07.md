## Approach and Implementation

* LangGraph Workflow: The main focus this week was to ensure the individual components of the workflow operate correctly. Joel has been working on the NQS Neural Network, and we met multiple times this week to make sure our inputs and outputs match our expectations. The expected inputs for the NQS model are supposed to be the model parameters of the TeNPy MPS and the expected outputs from the NQS model are supposed to be the ground state energy and the numerous quantum property observables calculated by TeNPy, such as the Double Occupancy per site, Charge Density, Charge Correlation Matrix, Spin Correlation Matrix, Spin Structure Factor, and Charge Structure Factor. There was an initial problem where, because Joel did not have access to the Kagome models generated by TeNPy, he was testing with square lattices. While that is not a major issue, we found out that the NQS model being used would not be able to scale higher for different sites. We want the model to be able to compute the quantum properties regardless of the lattice size. We solved this issue by adding a layer of Graphical Neural Networks to compute the properties, allowing for a Size-Agnostic output. Additionally, we added an input variable for the matrix size, the adjacency matrix, which the model can use to create the output matrices without having to re-initialize the NQS model for each layer.
* ED and MPS Discrepancies: I focused my efforts earlier this week to ensure that the Exact Oracle matched the results of MPS. After matching all constraints, I was able to match the majority of the results. However, there were some slight issues due to there being multiple ground states from exact diagonalization (a single eigenvalue (ground state energy) can have multiple eigenvectors (ground states)). I solved this issue by adding a perturbation of chemical potential to a single site. Since I was not considering chemical potential in either model, this addition gave a single ground state for each parameter.
* TeNPy Dataset: After the final verification, I ran the script to create 200 three-site Kagome models, 100 six-site Kagome models, and 50 nine-site Kagome models. I split the 200 three-site Kagome generation into two runs, which resulted in the right number of models but the model manager (CSV file for three-site Kagomes) refreshed during the second run and deleted the entries for the first hundred. To make sure the CSV files match, I will re-run the 200 three-site Kagome model generation in a single session.
